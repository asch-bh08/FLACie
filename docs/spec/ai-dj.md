# AI DJ: build spec (2026-10-25)

Background and research: `docs/research/ai-dj-free.md` on branch `research/ai-dj` (sections 10 and Appendix A are the design). Owner's decisions: Cloudflare Workers AI makes the voice; easy settings; the DJ can be on only for Android Auto, only for web, or only for one playlist or queue. Ships on Android + web + Windows together. Alexa is not in this build (its "Where" tick is left out until it is).

## How it works
1. When a song starts, the player asks the server about the **next** song (`PrepareAsync` in-process for web/Windows, `POST /api/dj/next` for Android).
2. The server decides whether to speak (settings, switches, frequency, variety; all in FLACie.Core so it is tested once), writes the line from templates, and starts making the MP3 with Cloudflare in the background. The answer is cached per (account, prev, next) so asking again gives the same answer.
3. When the player moves to that song **by itself** (auto-advance, not a skip), it plays the clip on a second small player over the start of the song, with the music ducked to the person's "Music under the DJ" level (30% by default; ramp 400 ms down, 600 ms up) and the clip at their "DJ volume" (90% of the music's volume by default). No queue item is added; play counting, the queue, the media session and Android Auto metadata are untouched.
4. If the server returns `ClipUrl = null` and `Backup = true` (only when the person chose **Device voice**), the device says `Text` with its own voice (Android `TextToSpeech`, browser `speechSynthesis`), ducking the music the same way. Otherwise the DJ keeps to one voice: see "One voice" below.
5. Pause, skip, seek, stop, a new queue: the clip stops at once and the music un-ducks.

## Which switch wins (FLACie.Core, tested)
1. `QueueDj` (Now Playing button, this queue only) if not null.
2. `Playlists[PlaylistId]` if the queue came from a playlist with an entry.
3. `Enabled && Settings.On(Surface)`.
Then the frequency/variety rules (Appendix A.4) and the silent conditions decide this transition. Often speaks with a chance of 0.5 once the one forced silent song after a line has passed (about one song in 3); Rare 0.30 after four (about one in 7). Every song speaks before each song with no draw and no forced silence; only songs marked "never", songs under 60 s, spoken word and (with Talk after skips off) skips stay quiet, so it uses about three times the lines of Often.

`TalkAfterSkips` (per person, default on): a skip no longer silences the next two songs; the listener hears the DJ on the songs they let play, and "Let's try something different" can still come after several skips. Off: skipping going on (`skippedRecently`) keeps the DJ quiet, as before. With it on, the web player also says a line over a song reached by Next or a tap in Up next: the answer kept for that song if there is one, otherwise it asks at once and says the line only if it arrives within 3 s and that song is still the one playing (a quicker skip, a pause or a seek drops it, so lines never stack). Off: only a song reached by itself brings a line.

The web player takes the answer about a song the moment that song starts loading, before anything else (the Autoplay lookup answering from its cache) can ask about the song after it.

## Shared types
`ipodsync/src/FLACie.Core/Dj/DjContracts.cs`: `DjSurface`, `DjChatty`, `DjSettings`, `DjSong`, `DjRequest`, `DjCue`, `IDjService`. Change them only by agreement (they are the contract between the three parts).

## HTTP (all under `/api/dj`, caller = cookie or `X-Emby-Token` + `X-Jellyfin-Server`, via `ApiEndpoints.CallerAsync`)
- `GET /api/dj/settings` → `{ enabled, chatty: "rare"|"often"|"every", phone, auto, web, windows, backup (ignored, kept for older apps), talkAfterSkips, style: "classic"|"chill"|"hype", playlists: { id: bool }, deviceVoice, volume: 0-100, duck: 0-100, songs: { matchKey: "always"|"never" }, voiceReady }` (style: Classic radio by default; Chill talks about a fifth less often, Hype a fifth more)
- `POST /api/dj/settings` → partial update with the same field names (type-checked, 400 on wrong types); `{ "playlist": { "id": "...", "on": true|false|null } }` sets or clears one playlist; `{ "song": { "title": "...", "artist": "...", "choice": "always"|"never"|null } }` sets or clears one song (the server keys it by `Matching.MatchKey`). Returns the GET shape. Any signed-in user, for their own settings only.
- `POST /api/dj/next` body (camelCase of `DjRequest`; `surface` "phone"|"auto"|"web"|"windows"):
  `{ surface, next: { title, artist, album, albumArtist, year, genre, durationMs, path, jellyfinId, trackNo, discNo }, prev: {...}|null, prevPlayedOut, skippedRecently, playlistId, queueDj, localHour, weekday, why, bond: "loved"|"new"|"unknown", queueStart?, queueName?, shuffled? }` (bond: only what the client knows for certain; the server fills "unknown" from the account's listening)
  `queueStart` (30 Oct): `next` is the first song of a queue just started from a playlist or album (`queueName`, `shuffled`) and `prev` is null; the DJ says one line for it ("Shuffling Pop... starting with Firework, Katy Perry"), by the usual switches, the song choices and the hello's chance, and the song after it passes in silence. The phone and the web send it from the play call only (never on a shuffle toggle mid-queue), for a named playlist or album page on shuffle; the line is said if it arrives within 6 s. In the listener's own playlist or queue (no `why`) the DJ never mentions skips, a change of direction or steering, and a feel is worded about the song ("a calmer one"); after a song by the same artist the artist is not named again.
  → `{ "speak": false }` or `{ "speak": true, "text": "...", "caption": "...", "clip": "/api/dj/clip/<id>.mp3"|null, "backup": bool }`
- `GET /api/dj/clip/{id}.mp3` → `audio/mpeg`. Waits up to 10 s if the clip is still being made; 404 if it failed or expired. Never counted as a play; not under `/stream`.
- Clips are kept in `{data}/dj-clips` by a hash of (voice, exact text), so nothing is made twice; `index.json` says when each was last used and past 200 MB the least recently used go. To make the free allowance last the day (`DjBudget`), a line is said whole (the model's, Llama 3.3 70B with 3.1 8B behind it) only while it leaves room for a reserve of pooled lines: a kept phrase ("Coming up,", a hello, "That was...") joined to a kept clip of the song's name. A hello with a first name in it is kept for that person only.

## The Windows app
The Windows app runs its own copy of the server (its own data folder), so on its own it would have its own DJ settings and no Cloudflare key. When the signed-in person's profile names the family's FLACie Web (`services.flacieweb.url`, set by the phone), the Windows app's DJ goes through that server instead (`FLACie.Server/Dj/HomeDj.cs`): settings and next-song answers come from its `/api/dj/settings` and `/api/dj/next` with the person's own Jellyfin token headers, and clips come through the local route `GET /api/dj/clip/r/{id}.mp3`, which fetches them from there. If that server can't be reached, the Windows app's own DJ takes over and the settings section says why.

## When Cloudflare fails
After a failed clip, new lines get no clip for 10 minutes (so the device's own voice says them if Backup voice is on); a clip made or a change to the voice settings ends the rest early. A clip that fails after its line was sent is said by the device's voice too, if it is still within the first 6 s of the song.

## Admin (server-wide, FLACie Web dashboard, admin only)
`{data}/dj.json` like `Notifier`: Cloudflare account id, API token (encrypted with IDataProtector, never returned; "leave empty to keep"), voice `melotts` or `aura-1:<speaker>`, daily cap (% of the 10,000 free neurons, default 50), plus a Test button and today's use. Optional `FLACIE_CLOUDFLARE_ACCOUNT` / `FLACIE_CLOUDFLARE_TOKEN` env bootstrap.
Cloudflare: `POST https://api.cloudflare.com/client/v4/accounts/{account}/ai/run/@cf/myshell-ai/melotts` `{ "prompt": text, "lang": "en" }`, or `.../@cf/deepgram/aura-1` `{ "text": text, "speaker": s, "encoding": "mp3" }`. Accept either a binary `audio/mpeg` body or JSON `{ result: { audio: <base64> } }`. Cost estimate per line: MeloTTS 18.63 neurons per audio minute (estimate audio length from words at 2.6 words/s); Aura-1 1,363.64 per 1,000 characters. Over the cap or failing → no clip (Backup path). Clips cached in `{data}/dj-clips/` by hash of voice+text, oldest pruned past 3,000 files. `api.cloudflare.com` joins the `FLACIE_CATALOG_REDIRECT` test seam.

## Lines written by a model (2026-10-26)
The planner still decides when the DJ speaks and writes a template line. When the dashboard's "Write the lines with Workers AI" is on (default), `DjService` then asks `@cf/meta/llama-3.1-8b-instruct` to reword it once per decision (`FLACie.Core/Dj/DjWriter.cs`: a warm, witty, UK-English presenter; the facts are the next and previous songs, album, year, time of day, skips, the recommender's why and the last 6 lines to avoid). The answer is checked (one or two sentences, at most 25 words, names the song or artist, no name or number outside the facts, no emoji, hashtags or cheesy words, not opening like the last line) and respelt with `DjPronounce`; any failure, 2.5 s without an answer, or too little of the cap left for the line and its clip, says the template line. The model's neurons count into dj-usage. Default voice: Aura-1 Helios (an older dj.json still on MeloTTS moves to it once); near the cap, Aura lines not yet made are said by MeloTTS. The dashboard has a Test button per voice.

## Timed to the intro (2026-10-26)
The vibe pass also works out each song's intro (`DjIntro`, kept as `Vibe.Intro` in data/vibe.json): the first line of synced lyrics, else the first clear lift in the level envelope after a quieter start; used only at confidence 0.5 or more. `DjCue.IntroMs` (`"introMs"` in POST /api/dj/next, null when not known) carries it to the players, and `DjTiming` (Kotlin twin `playback/DjTiming.kt`) places the clip: it ends 0.5 s before the vocals when it fits, otherwise it starts with the song and the song is held back (silent, then from its start) at most 1.5 s. The writer is asked for a line of about the words that fit (2.6 words a second). Details: docs/dj-timing-report.md.

## One voice, DJ volume, a choice per song (2026-10-26)
- **One voice.** A session never mixes voices. The clip is always made in the dashboard's voice: near the cap there is no MeloTTS stand-in for Aura any more, and a failed or capped clip is never handed to the device's voice. When the voice can't be used (the cap, Cloudflare failing), the planned template line or its pooled form is said if its clips are already kept in the same voice (`DjClips.Cached`, `DjClips.CachedPooled`; ids hash the voice, so another voice's parts are never joined in); otherwise the DJ stays quiet. The device's voice is used only when the person turns on **Device voice** (`DjSettings.DeviceVoice`), and then for every line, with no clip made. The old `backup` switch is ignored.
- **DJ volume** (`volume`, default 90 %) scales the clip (and the device voice) against the music's volume; **Music under the DJ** (`duck`, default 30 %) is the level the music ducks to. Sliders in Settings → DJ on the web, Windows and Android; applied by `flacie.djLevels` (web) and `DjPlayer` (Android) before each line.
- **Per song** (`songs`, by match key): "DJ: always introduce this song" speaks before it whenever it comes up (it beats the chance, the forced silence and the quiet rules such as a short song or the next album track, but not the switches or the cap); "DJ: never talk over this song" keeps the DJ quiet for it; "DJ: default" clears the choice. In every song menu (web/Windows track lists, Songs, Now Playing; the Android song sheet), with the current choice ticked. A change makes the server plan the next song again at once.
