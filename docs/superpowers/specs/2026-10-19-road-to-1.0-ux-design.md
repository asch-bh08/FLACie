# Road to FLACie 1.0 (beta 100): UX, QoL and UI

Draft for review, 2026-10-19. Status now: beta 71 (web, Android with Retro built in, Windows MSI).

## Goal
At beta 100, FLACie drops "beta". Someone new should be able to install it on web, Android or Windows, sign in to Jellyfin (or a NAS), and play their library without help. It should feel like one app on all three, with nothing broken or half-finished showing.

## What "1.0 ready" means (the release bar)
- The same features, words and layout on web, Android and Windows. Where a platform can't do something, it says why, and nothing is hidden.
- No known bug that loses data, skips songs or empties playlists. A server restart never breaks an open tab: it reconnects by itself (today the person has to reload).
- Every screen works at phone, tablet and desktop sizes, by touch, mouse and keyboard.
- Accessibility: WCAG AA contrast, screen-reader labels on every control, visible keyboard focus, and reduced motion respected (Retro scenes included).
- First run under 2 minutes from install to the first song playing.
- Memory and CPU budgets hold: web tab under 300 MB, the desk under 15% CPU on a mid-range phone.

## 1. UX (how it flows)
1. **First-run guide**: server address (with Jellyfin found on the LAN automatically), sign-in or Quick Connect, then a short "here's Home, Search, Retro" tour that can be skipped.
2. **Reconnect instead of reload**: after a deploy or a dropped connection, the web page keeps playing what's buffered, shows "Reconnecting…", and picks up the session again.
3. **One settings model**: settings are grouped the same way on all three (Playback, Library, Downloads, Appearance, Retro, Account, About), with search across settings.
4. **Retro ↔ FLACie handoff**: shuffle, repeat, queue, lyrics and covers stay in sync both ways (today Retro on Android only follows FLACie).
5. **Empty and error states**: every list says what to do when it's empty, every error says what happened and offers a retry, and no raw exception text is shown (today the login shows `e.Message`).
6. **Undo** for removing from a playlist or queue, and for clearing the queue.
7. **Offline is clear**: downloaded songs are marked, an "Offline only" filter, and a banner when the server can't be reached.

## 2. QoL (small things that save time)
- Queue: drag to reorder, "play next" and "add to queue" everywhere, save the queue as a playlist, and the queue kept across restarts on web too.
- Keyboard shortcuts on web/Windows (space, arrows, / for search, ? for the list).
- Media keys and the OS media panel on Windows; lock screen and Android Auto checked.
- Sleep timer, crossfade/gapless toggle, ReplayGain toggle on every platform.
- Search: recent searches, typo tolerance, filter chips (songs, albums, artists, playlists).
- Multi-select in lists (shift/long-press) for add to playlist, download or remove.
- Remember scroll position and sort per list.
- "Continue where you left off" on Home.
- Download manager: pause/resume, Wi-Fi only, storage used per album.
- Share a song or album as a link (web).

## 3. UI (how it looks)
- **A design pass with tokens**: one colour, type, spacing and radius scale shared by web (CSS variables), Android (Compose theme) and Windows. Light, dark and system themes everywhere.
- Now Playing: big cover, colours from the cover, a clear progress bar with time, lyrics on the same screen, the Retro button kept.
- Lists: consistent row height, cover size and touch targets (44 px minimum), skeleton loading instead of spinners.
- Album and artist pages: header with cover/photo, play and shuffle buttons, year/format/bit-depth badges.
- Icons from one set, no mixed styles.
- Motion: short (under 200 ms) and compositor-only; off with reduced motion.
- Retro: keep the film-photo look; finish its phone layouts and desk performance on real phones.

## Milestones

## How we'll test it
- Each item: a Playwright or unit test first (TDD), and a screenshot check on phone/tablet/desktop.
- A by-hand checklist per platform before each RC (docs/BY-HAND-CHECKS.md, extended).
- Accessibility: axe checks in Playwright on every page.

## Not in 1.0
- New sources besides Jellyfin and NAS, social features, a Play Store release, iOS.
